## Part 1: Files to KEEP as JavaScript

### 1.1 `eslint.config.js` ⚠️ KEEP AS JS
**Reason:** ESLint flat config requires `.js` extension for ESM compatibility with the ESLint CLI. Converting to TypeScript would require additional build steps and may break CI/CD.

```javascript
// Current: ESM with dynamic imports
import js from '@eslint/js';
import tseslint from '@typescript-eslint/eslint-plugin';
// ... configuration exports
```

**Module System:** ESM  
**Dependencies:** @eslint/js, @typescript-eslint/*, eslint-plugin-*, globals  
**Referenced By:** `npm run lint`, ESLint CLI

## Part 5: Breaking Change Risks

### 5.1 CommonJS → ESM Conversion
Files using `require()` must be converted to `import`:
- `scripts/build-assets-manifest.js`
- `scripts/build-data.js`
- `scripts/ensure-data.js`
- `scripts/preflight.js`
- `scripts/register-commands.js`

### 5.2 Package.json Script Updates
```json
{
  "scripts": {
    // BEFORE
    "validate:urls": "node scripts/validate_database_urls.js",
    "register:commands": "node scripts/register-commands.js",
    
    // AFTER
    "validate:urls": "tsx scripts/validate_database_urls.ts",
    "register:commands": "tsx scripts/register-commands.ts"
  }
}
```

### 5.3 Render.yaml Updates
Worker start commands may need updates if entry points change.

### 5.4 CI/CD Impact
- GitHub Actions may need `tsx` available
- Build times may increase slightly due to type checking
