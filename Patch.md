# AI PROJECT MANAGER CONTRACT
Last Updated (UTC): 2025-10-26T12:50:00Z
Revision: 1.23

This repository uses **Patch.md** as the single source of truth for automated, AI-driven development flow.
The AI reading this file must follow the loop and rules exactly.

## PRIME DIRECTIVE
Always read and parse `Tasklist.md` first. Work only on tasks whose `status: READY`.
After completing a task, update `Tasklist.md` *convulsively* (immediately) to reflect:
- `status: DONE` for the completed task (with a brief outcome note)
- Any newly-unblocked tasks moved to `status: READY`
- Any newly-discovered subtasks appended (with unique IDs) and appropriate status

## OPERATING LOOP
0. **Meta Visibility Check (MANDATORY)**
  - Confirm you can open `Patch.md`, `Tasklist.md`, and `Prompt.md` locally.
  - If any are inaccessible, stop and ask a human to refresh or provide updated copies before proceeding.
1. **Load Task Graph**
   - Read `Tasklist.md`.
   - Build an ordered plan from tasks where:
     - `status: READY`
     - All `depends_on` are `DONE`.
   - Never start tasks not marked `READY`.
    - CI guard (`scripts/guard_meta.sh`) fails when the READY queue is empty (ignoring `META.UNBLOCK.READY_SEED`); promote a PROPOSED task or add a fresh READY item before merging.

2. **Execute**
   - For the first READY task in dependency order:
     - Apply code changes using **PATCH BLOCKS** format (below).
     - Keep changes minimal, reversible, and scoped to the task.
     - Run/adjust tests if present.

3. **Update Tasklist**
   - Mark the executed task `DONE`.
   - For any tasks now unblocked, change `status` to `READY`.
   - If you discover missing steps, create new tasks with unique `id` and clear `acceptance_criteria`.
  - Use `npm run tasks:archive` to keep only the 100 most recent `status: DONE` entries in `Tasklist.md`; the script writes older entries to `ops/ARCHIVE/tasks-YYYYMMDD.md` (skipping IDs still referenced by active tasks).
  - **Coupling Guard (CI-enforced):** Any PATCH touching `src/**`, `tests/**`, or other build-critical paths must include a `# TASKLIST UPDATE` diff. CI (`guard-meta.yml`) will fail otherwise.

4. **Commit**
   - Generate a commit message using the template below.
   - Multiple small commits are preferred over one giant diff.

5. **Postflight: Ensure Readiness (see below), then Repeat**
   - Before ending the run, execute the Postflight checklist to guarantee the next worker can start immediately.

## Readiness — Preflight and Postflight (cannot skip)
Preflight (at activation, before choosing a task):
- If Tasklist.md has zero READY tasks (excluding the seed), automatically promote the oldest eligible PROPOSED whose dependencies are DONE. If none exist, insert META.UNBLOCK.READY_SEED as READY. Then set ops/NEXT.yaml:next_task_id to that item.
- If ops/NEXT.yaml:next_task_id is NONE or points to a non-READY task, fix it using the rule above.

Postflight (before exiting the run):
- Guarantee Tasklist.md has ≥1 READY task (excluding the seed) and ops/NEXT.yaml points to one of them with a minimal files_hint.
- If not, promote the oldest eligible PROPOSED (or inject META.UNBLOCK.READY_SEED) and retarget NEXT accordingly.
- Write a one-paragraph plain-text echo into Prompt.md describing exactly what was promoted and why.

## Plain-text PATCHSET Echo (strict)
- The echo lives between “PATCHSET:ECHO BEGIN/END” in `Prompt.md` and must be human-readable sentences.
- Do not include ``` blocks, diff fences, full-file objects, or JSON. Keep it strictly text so chat renderers do not reflow or embed.
- Include HEAD (or “pending-local”), a concise summary, TasklistDiff true|false, a tests note, and explicitly state which READY task NEXT points to (and why that task was chosen). Reference `CRITICAL.md` boot order when explaining next steps.

## ROUTER NETWORK (City Roadway Model)
- **Per-directory router:** A `ROUTER.md` lives in each directory that contains patchable code or docs. It declares Title, Purpose, Owned globs, and a short “Where to next” note.
- **Router-of-routers:** `ops/ROUTER_INDEX.yaml` lists every discovered router with path, purpose, and last-updated timestamp. It is regenerated by `scripts/update_router_index.sh` and must be refreshed before task selection.
- **Consistency rule:** If a PATCHSET touches any file under a routed directory, update that directory’s `ROUTER.md` (timestamp + brief note) in the same PATCHSET and re-run the index script.
 - **Name/Case rule (MANDATORY):** Router entries and canonical docs must match filesystem spelling and case. CI runs `scripts/verify_router_links.sh` to block mismatches and suggest nearest matches.

## META UPDATE REQUIREMENT (MANDATORY)
- Every PATCHSET must, at minimum, update `Prompt.md` (Timestamp + Revision + “Last Repo Changes”).
- If `Tasklist.md` or `Patch.md` are edited, both must have their header timestamps/revisions bumped in the same PATCHSET.
- If unsure what to change: update `Prompt.md` with a brief note under “Last Repo Changes” and bump its header; then stop or add a tiny precursor task.

### Hotfix Compatibility
- The Hotfix Engine (trigger `ACTIVATE: HOTFIX ENGINE`) performs **no PATCHSET blocks** but **must** still:
  - Bump `Prompt.md` (Timestamp, Revision, Last Repo Changes).
  - Update `Tasklist.md` (ensure a hotfix task exists, mark it DONE with outcome).
  - Update any touched directory `ROUTER.md` (timestamp + short note) and keep routing metadata consistent.
- Hotfixes may edit `Patch.md` only when the contract itself requires updates for the urgent fix.
- When a human request lacks an explicit activation trigger, treat it as `ACTIVATE: HOTFIX ENGINE` and follow the hotfix loop without prompting for clarification.

### Worker Prompt Requirement
- `Prompt.md` MUST contain the section titled exactly “AI Worker Prompt (copy/paste for Copilot/GPT)”.
- When material workflows change (NEXT/TOUCHMAP/policies), refresh that section accordingly.

### Hard Routing Policy (MANDATORY)
- The AI MUST load `ops/ROUTER.yaml` and use it to determine where to read next and where writes are allowed.
- Before any task, check `ops/INBOX/notes.md`; if its `Timestamp (UTC)` is newer than `ops/NEXT.yaml:last_notes_read_utc`, ingest those notes and set `last_notes_read_utc` during the PATCHSET.
- Writes outside the `meta_write_whitelist` or the task’s `ops/TOUCHMAP.yaml` paths are forbidden unless a new subtask is created that justifies expanding TOUCHMAP.
- If routing conflicts arise, stop and add a PROPOSED task to reconcile router vs. reality; update Prompt “Last Repo Changes”.

## Activation Trigger (MANDATORY)
Trigger phrase (case-sensitive): `ACTIVATE: PATCH ENGINE`
On trigger, follow Router → INBOX → NEXT → Tasklist → TOUCHMAP → Patch → Prompt sequence and emit one PATCHSET + Commit Message.

## Hotfix Trigger (No-PATCHSET Mode)
Trigger phrase (case-sensitive): `ACTIVATE: HOTFIX ENGINE`
Use the Hotfix Engine for urgent, tightly-scoped changes. It follows the same sequence as the Patch Engine but **does not** emit a PATCHSET block. Only edit:
- The files listed in `ops/HOTFIX_PLAN.yaml: files_hint`
- Minimal meta (Prompt.md, Tasklist.md, ops/RECOVERY.yaml, ops/HOTFIX_PLAN.yaml)
- Directory-local ROUTER.md for any touched area (timestamp + one-line note)
**Do not** edit Patch.md unless explicitly directed or strictly necessary for the fix.
Hotfix commits still **must** bump Prompt.md and update Tasklist.md.

### History Discipline (MANDATORY)
- Maintain a “Recent Change Ledger (last 200)” section in `Prompt.md` between `<!-- LEDGER:BEGIN -->` and `<!-- LEDGER:END -->`.
- Regenerate using `npm run docs:update-ledger` (scripted) to include changed files and approximate line ranges.
- CI verifies the ledger includes the HEAD commit; keep the ledger machine-generated and unedited.

### Embedded PATCHSET Echo (MANDATORY)
- After every applied PATCHSET, update `Prompt.md` section “Embedded PATCHSET Echo (for quick audit)” between markers:
  - `<!-- PATCHSET:ECHO BEGIN -->` … `<!-- PATCHSET:ECHO END -->`
- The echo must contain either:
  1) The exact PATCHSET and Commit Message just applied (verbatim), including the HEAD short SHA, or
  2) A one-line justification starting with `NO-ECHO-REASON:` explaining why the echo is omitted (e.g., secrets, large binaries), followed by a brief summary.
- Format the echo contents as plain text sentences (avoid Markdown list markers) so downstream renderers do not reflow the audit.
- If the echo cannot be produced, stop and add a PROPOSED meta task to fix echo generation.
  - When code paths are modified, add a single line in this block with `TasklistDiff: true|false` so humans can quickly audit coupling coverage.

## READY DEFINITION
A task is `READY` if:
- It has clear `acceptance_criteria`
- All `depends_on` are `DONE`
- Scope is confined to allowed paths

If a task is ambiguous, create a small precursor task (`status: PROPOSED`) with a clarifying patch to reduce ambiguity, then mark it `READY`.

## DONE DEFINITION
A task is `DONE` if:
- The change compiles (if applicable) and basic lints pass
- Acceptance criteria are demonstrably met
- `Tasklist.md` records the outcome under that task

## FAILURE & ROLLBACK
If a PATCHSET introduces breakage:
- Emit a new PATCHSET to revert the specific files to their previous state.
- Mark the task `BLOCKED` with a short reason and create a `FIX:` task that is `READY`.

## MODIFICATION POLICY: Patch.md & Tasklist.md

These files are the contract and the task graph. Update them deliberately and traceably.

When it’s OK to update `Patch.md`
- Contract evolution that improves automation (e.g., new PATCHSET rules, safety rails, or fast-path steps).
- Fixing ambiguous or conflicting instructions that block work.
- Adding/removing sections that improve clarity or determinism (e.g., new meta policies).
- Clipboard maintenance (the PATCH CLIPBOARD footer is the only place for live PATCHSET staging).

How to update `Patch.md`
1. Prefer doing it under a dedicated META task (id prefix `META:` or `T0.*`) with clear acceptance criteria.
2. Use a surgical diff in the PATCHSET; avoid rewriting the entire file unless necessary.
3. Include a `# TASKLIST UPDATE` that:
   - Marks the META task DONE.
   - Adds any follow-up tasks (e.g., updating `ops/CRITICAL.md`, `ops/NEXT.yaml`, or `ops/TOUCHMAP.yaml`).
4. Never store secrets; never remove the PATCH CLIPBOARD footer.

### Canonical Filenames (DO NOT RENAME)
These filenames are contractual and referenced by Render Build Filters. Never change their spelling or case.
- `Patch.md`
- `Tasklist.md`
- `Prompt.md`
- `ops/PATCH_POLICY_BACKUP.md`

If any of these are renamed, CI will fail (see `.github/workflows/guard-docs.yml`), and the AI must restore their exact names before proceeding.

When it’s OK to update `Tasklist.md`
- Normal lifecycle transitions: READY → IN_PROGRESS → DONE, adding brief outcome notes.
- Unblocking newly-eligible tasks by flipping to READY.
- Adding discovered subtasks:
  - Use concise `id` (e.g., `T4.1a`) and clear `acceptance_criteria`.
  - Set initial `status: PROPOSED` or `READY` if immediately actionable.
- Marking tasks BLOCKED with a short reason and creating a `FIX:` task.

How to update `Tasklist.md`
1. Always via the `# TASKLIST UPDATE` unified diff within the current PATCHSET.
2. Keep the history lightweight: outcome notes belong on each task; deeper context goes to `Prompt.md` (Revision History) if architectural.
3. Avoid mass reformatting; preserve existing order and phases unless a META task explicitly reorganizes them.
4. When DONE history grows beyond 100 entries, run `npm run tasks:archive` to archive the oldest completed tasks into `ops/ARCHIVE/`.

Meta-Update Workflow (quick checklist)
1. Create/choose a META task (or the current task if its acceptance criteria require contract changes).
2. Edit `Patch.md`/`Tasklist.md` with minimal diffs; reflect any crossfile implications (`ops/NEXT.yaml`, `ops/CRITICAL.md`, `ops/TOUCHMAP.yaml`).
3. Update `Tasklist.md` (status changes, new tasks).
4. Commit with a message that states why the meta-change was necessary.

# FILE: scripts/dev_tag_guard.sh

``full
#!/usr/bin/env bash
set -euo pipefail

# Guard: Ensure DEV/system files carry @last_task_id and collect untagged non-vital files for pruning.

ROOT="$(git rev-parse --show-toplevel 2>/dev/null || echo ".")"
cd "$ROOT"

PRUNE_LIST="ops/DEV_PRUNE_LIST.txt"
KEEP_FILE="ops/DEV_KEEP.yaml"
: > "${PRUNE_LIST}"

# Patterns
VITAL_WHITELIST='^(src/|data/|render\.yaml$|package\.json$|tsconfig\.json$|prisma/|routes/prod/)'
DEV_ZONES='^(ops/|scripts/|routes/dev/|masterroutetable\.md$|DNS\.md$|Patch\.md$|Tasklist\.md$|Prompt\.md$)'

# Collect keep overrides
declare -A KEEP
if [[ -f "${KEEP_FILE}" ]]; then
  while IFS= read -r line; do
    [[ -z "$line" || "$line" =~ ^# ]] && continue
    KEEP["$line"]=1
  done < "${KEEP_FILE}"
fi

has_last_task_id () {
  head -n 30 "$1" | grep -Eq '@last_task_id:\s*[A-Z0-9\.\-]+' || return 1
}

has_dev_tag () {
  head -n 30 "$1" | grep -Eq '@dev-only' || return 1
}

is_text () {
  # Treat binary as non-text (skip)
  file -b --mime "$1" | grep -q 'text/' || return 1
}

fail=0
while IFS= read -r f; do
  # Skip directories and deleted
  [[ -d "$f" ]] && continue
  [[ ! -f "$f" ]] && continue
  # Skip binary files
  is_text "$f" || continue

  # vital paths: never prune
  if [[ "$f" =~ $VITAL_WHITELIST ]]; then
    # metadata optional here (not enforced)
    continue
  fi

  # dev zones: must have @last_task_id
  if [[ "$f" =~ $DEV_ZONES ]]; then
    if ! has_last_task_id "$f"; then
      echo "::error file=$f::Missing @last_task_id header in DEV/system file." >&2
      fail=1
    fi
    continue
  fi

  # non-vital, not in dev zones
  # if explicitly kept, skip
  if [[ -n "${KEEP[$f]:-}" ]]; then
    continue
  fi

  # if not explicitly tagged DEV, schedule for pruning
  if ! has_dev_tag "$f"; then
    echo "$f" >> "${PRUNE_LIST}"
  fi
done < <(git ls-files)

if [[ $fail -ne 0 ]]; then
  echo "::group::DEV tag guard summary"
  echo "Missing @last_task_id found. See errors above."
  echo "::endgroup::"
  exit 1
fi

if [[ -s "${PRUNE_LIST}" ]]; then
  echo "::notice::DEV prune candidates listed in ${PRUNE_LIST}"
else
  rm -f "${PRUNE_LIST}"
fi
``

# FILE: scripts/dev_sanitize.sh

``full
#!/usr/bin/env bash
set -euo pipefail

ROOT="$(git rev-parse --show-toplevel 2>/dev/null || echo ".")"
cd "$ROOT"

PRUNE_LIST="ops/DEV_PRUNE_LIST.txt"
if [[ ! -f "${PRUNE_LIST}" ]]; then
  echo "No prune list present; nothing to sanitize."
  exit 0
fi

while IFS= read -r f; do
  [[ -z "$f" ]] && continue
  if [[ -f "$f" ]]; then
    printf '%s\n' "<!-- DEV-PRUNED: This file was pruned during DEV finalize. Safe to delete. -->" > "$f" || true
    # Fallback for code files (if markdown header not desired)
    if [[ "$f" =~ \.(ts|js|sh)$ ]]; then
      printf '%s\n' "// DEV-PRUNED: This file was pruned during DEV finalize. Safe to delete." > "$f" || true
    fi
    echo "::notice file=$f::pruned"
  fi
done < "${PRUNE_LIST}"

rm -f "${PRUNE_LIST}"
``

# FILE: scripts/ensure_ready_next.sh

``full
#!/usr/bin/env bash
set -euo pipefail

# Ensure there is ≥1 READY task and NEXT.yaml points to a READY task.
# Suggest a candidate if needed but do not auto-edit files (human/AI will).

has_ready=$(grep -Ec '^\s*status:\s*READY\b' Tasklist.md || true)
if [[ "${has_ready}" -eq 0 ]]; then
  echo "::error::Tasklist.md has zero READY tasks. Promote an eligible PROPOSED item or add a READY seed."
  # Suggest the first eligible PROPOSED whose deps are DONE
  awk '
    BEGIN{RS=""; FS="\n"}
    /- id:/ {
      id=""; st=""; deps=""
      for(i=1;i<=NF;i++){
        if($i ~ /^- id:[[:space:]]*/){ id=$i; sub(/^- id:[[:space:]]*/,"",id) }
        if($i ~ /^[[:space:]]*status:/){ st=$i; sub(/^[[:space:]]*status:[[:space:]]*/,"",st) }
        if($i ~ /^[[:space:]]*depends_on:/){ deps=$i; sub(/^[[:space:]]*depends_on:[[:space:]]*/,"",deps); gsub(/[\[\],]/," ",deps) }
      }
      if(st=="PROPOSED"){ print id "|" deps }
    }
  ' Tasklist.md | while IFS='|' read -r id deps; do
      ok=1
      for d in $deps; do
        [[ -z "$d" ]] && continue
        if ! grep -qE "^- id: ${d}$([[:space:]]|\n).*^[[:space:]]*status:[[:space:]]*DONE\b" -n Tasklist.md; then
          ok=0; break
        fi
      done
      if [[ $ok -eq 1 ]]; then
        echo "::notice::Eligible PROPOSED for promotion: ${id}"
        break
      fi
    done
  exit 1
fi

current_next=$(awk 'match($0, /^next_task_id:\s*(.*)$/, a){print a[1];exit}' ops/NEXT.yaml | tr -d '"')
current_next=${current_next:-NONE}
if [[ "$current_next" == "NONE" ]]; then
  # Suggest the first READY id
  ready=$(awk '
    BEGIN{RS=""; FS="\n"}
    /- id:/ {
      id=""; st=""
      for(i=1;i<=NF;i++){
        if($i ~ /^- id:[[:space:]]*/){ id=$i; sub(/^- id:[[:space:]]*/,"",id) }
        if($i ~ /^[[:space:]]*status:/){ st=$i; sub(/^[[:space:]]*status:[[:space:]]*/,"",st) }
      }
      if(st=="READY"){ print id; exit }
    }
  ' Tasklist.md)
  if [[ -n "$ready" ]]; then
    echo "::notice::NEXT.yaml is NONE. Suggested next_task_id: ${ready}"
    exit 0
  fi
fi

echo "READY queue and NEXT pointer look sane."
```
